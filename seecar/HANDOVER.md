## 4. 第3期で「こちらが決めたこと」（山田さんに確認中）

- 宝は地面に埋まっていて、上に土の山（3×3マス、高さ3、淡い茶色 #d9b98c）がかぶさる。上から3回掘る（ドリルジャンプ1回で1段）か、正面から壊すと宝が出て、触ると拾える。
- ドリルアタック：正面のマス（向きを4方向に丸めた1マス先）を、自分の足元の高さまで下げる。
- ドリルジャンプ：跳ぶ→逆さ→潜る→足元を1段下げる→弾んで戻る。「すすむ」を押しながらだと1マス前を掘る。
- 移動はマス目に縛られない自由な向き。スワイプで向き（視点）が回る。
- 「どっちが はやい？」のスタートは、2人から宝までの道のりが同じになるよう選ぶ（全見本で差0〜1）。
- 見本の地図は、宝の部屋に入るまでに壊す壁が6マス以内になるよう線を細くし、壁の薄い領域を優先して宝を置く。
- 記録は「くらべっこの きろく」（`pixsee.record`）。勝ち負けの言葉は使わない。

## 5. ファイルの地図（`seecar/` の中）

- `src/`：ゲームの部品。`python3 build.py vN` で1ファイル `dist/seecar_vN.html` にまとめる。結合の順番は sfx → mapgen → seeker → world → net → ui。
  - `world.js`（3D世界。移動・ジャンプ・掘る・宝・ソナー・CPU・カメラ。いちばん難しい）
  - `seeker.js`（シーカーの3Dモデル。山田さんの3Dを移植したもの）
  - `mapgen.js`（画像→地形、宝と土の山、スタート、見本地図11枚）
  - `ui.js` / `style.css` / `index.html`（6つの画面、ボタン、ソナー、設定、記録）
  - `net.js`（PeerJS通信）、`sfx.js`（合成の効果音）
- `CONTRACT.md`：部品どうしの取り決め（関数名・引数・イベント）。末尾の「第3期の追加」がいまの決まり。部品を直すときは必ずここに合わせる。
- `dist/`：結合した版。v1〜v8 のほか、途中確認用の `v5dev`、`v6w`、`v7dev`、`v8ui`、`v8w` もある（消してよいが、消す前に確認）。
- `test/`：確認の仕組み。採点結果 `critic*.md`、採点用の数値 `values_v*.md`、画像 `shots/`。
- `ab/`、`blind/`：OpusとSonnetの比較実験（第1期の4回目の修正。Opus版が7.00対6.86で勝ち、土台に採用）。
- `ref_pixsee/`：山田さんの添付ファイル。

## 6. 確認のしかた（作業環境の注意）

- 作業環境からはCDN（cdnjs、unpkg）とPeerJSの公開サーバーにつながらない。`test/harness.js` の `openPage` を使うと、手元に入れた three r128 と PeerJS 1.5.4 に差し替えてPlaywrightで開ける。`startPeerServer(ポート)` で手元の中継サーバーを立てられる。
- 部品は `test/` で `npm install` 済み（`three@0.128.0`、`peerjs@1.5.4`、`peer@1.0.2`）。`node_modules` はコミットしていないので、新しい環境では `cd seecar/test && npm i three@0.128.0 peerjs@1.5.4 peer@1.0.2` が要る。
- 通し確認：`cd seecar/test && E2E_FILE=/home/user/my-first-repo/seecar/dist/seecar_v8.html PEER_PORT=9861 node e2e.js 名前`（数分〜十数分）。`ONLY=solo|cpu|settings|online` などで一部だけ。
- 3D世界：`node world3_run.js`。地図：`node mapgen_test.js`。
- 作業環境のブラウザは描画がソフトウェアで非常に遅い（数コマ/秒）。ゲーム内の時間は実時間より遅く進む（1コマ最大0.05秒）。重い確認を同時に2つ走らせると、通信の確認が落ちることがある（5秒届かないと切断とみなすため）。1つずつ流すこと。PEER_PORT は確認ごとに変える。
- 日本語フォントは作業環境では IPAゴシックなどで、iPad（ヒラギノ）と違う。四字熟語の地図は字をフォントで描いているので、iPadでは宝の位置や壁の厚さが変わる可能性がある（未確認）。

## 7. 進め方（これまでのやり方）

- ガントレットループ（`anthropic-skills:gauntlet-loop`）とモデル分業（`anthropic-skills:model-bungyo`）で進めてきた。
  - 作る担当と採点担当を分ける。採点担当には作った経緯・前の点数・過去の画像を見せない。
  - 採点の前に Haiku で数値を `values_vN.md` に書き出し、Opus が採点表で採点し、`critic*.md` に書く。
  - 3D世界（world.js）と採点は Opus、ほかの部品は Sonnet。見た目の難しい修正は、比較実験の結果から Opus に任せた。
  - 1期あたり2ラウンド（作る→採点→直す→採点）で区切って報告し、山田さんへ返信してきた。
- ユーザー（リポジトリのオーナー）の希望：結論から書く、専門用語を避ける、推測は「推測」「未確認」と書く、取り消せない操作（送信など）の前は確認。ただし山田さんへの返信は、11/1夜と11/3の2回、ユーザーから「確認なしで返信してよい」と言われて自動で送った。**この許可はその回ごとのもの。次に送るときは改めて確認すること。**
- この作業環境では、作業の区切りごとにコミットとプッシュをするよう求める仕組み（停止時の確認）が入っている。
