見つめて見つけて ほシーカー（SEE-CAR）作成メモ

ファイル：seecar.html（1ファイル）　対象：iPadを横にして使う想定　必要なもの：インターネット接続（Three.jsとPeerJSをCDNから読み込むため）

仕様書の「■1 ツールキッチンの基本ルール」をどう作ったか

仕様作り方
1 画面レイアウト100dvh・position:fixed; inset:0 で固定。16:9の枠を中央に置き背景は黒。中の寸法はすべて cqmin などで指定し、はみ出さないようにした。
2 縦持ち警告縦向きのときは全体を覆う警告を出し、プレイ中なら一時停止。文言は表記ルールに合わせて「スマホを よこに してね！」とひらがなにした。
3 誤操作防止すべてのボタンを共通の関数で登録し、押した瞬間に stopPropagation と preventDefault を実行。例外：画像を選ぶ入力欄だけは止めると選択画面が開かなくなるため、ボタンの上に透明に重ねて既定の動作を残した。
4 ズーム・メニュー防止* { user-select:none; touch-action:none; } と contextmenu の無効化。拡大も禁止。
5 6ステート起動 → タイトル → せってい（地図選び・通信の待ち合わせ）→ プレイ → みつけた！ → おしまい の6画面で切り替え。
6 ホームボタン右上に白い丸の家のボタンを常に最前面で表示（safe-area対応）。押すと「おわりにしますか？」を出し、その間はゲームを止める。誤って終わらないよう「いいえ」を大きく目立たせた。
7 進行ボタン画面を進めるボタンはすべて共通の置き場に集め、同じ大きさ・同じぴょんと跳ねる動きにそろえた。
8 日本語表記はじめる／しゅっぱつ！／みつけた！／もういちど／おわる など。漢字は四字熟語の地図名だけで、読みのひらがなを添えた。

仕様書の「■2 コアロジック」をどう作ったか

仕様作り方
A タイトルCSSで黄色い☆を描き、その中に「ほ」、横に「シーカー」「SEE-CAR」を配置したロゴ。
B 画像→地図明るさを0〜10の11段階の高さにする（白＝0の道、黒＝10の壁）。画像1画素＝2×2マス。そのままだと写真1枚で数十万ブロックになりiPadで動かないため、画像を長い辺64画素に縮めてから地図にした（最大128×128マス）。縮めると塗り絵の細い線が消えるので、各画素の範囲で一番濃い色を高さに使い、線が途切れないようにした。
C 宝の場所壁（高さ9以上）以外のマスをつないで領域に分け、地図の端に触れていない領域を「囲まれた領域」とする。その中で一番小さい領域の、中心に最も近いマスに宝石を置く。塗り絵の線のすき間や汚れを拾わないよう、16マス（画像で4画素）未満の領域は除外。中心が領域の外に出る形でも、必ず領域の中に置く。
D シーカー丸い車体・キャタピラ・砲塔・目のある戦車を基本の立体の組み合わせで作成（赤と青）。1マスずつ進み、90度ずつ向きを変える。高さの差が1段以内なら滑らかに上り下りし、それ以上は「ぶつかる」動きで止まる。ジャンプなし。
E 視点切り替えめ（1人称）／うしろ（斜め後ろ）／そら（俯瞰）をボタンで順に切り替え、カメラは滑らかに移動。俯瞰は高さ20だと大きな地図が入りきらないため、地図全体と宝が見える高さまで上げる。
F 大砲黒い玉が山なりに飛び、向いている方向の2マス先と3マス先の高さを0にする。破片・煙・閃光・画面のゆれと「ドゴォーン！」の文字を出す。弾は戦車をすり抜ける。
G 通信対戦ホストが4桁の番号を表示し、ゲストは数字ボタンで入力してつなぐ。地図は接続時に1回だけ送る（これが無いとゲストに地図が無いため）。以後は戦車の位置・向き・色・動き（1秒に10回）と、壊したマスだけを送る。相手が抜けたら「あいてが いなくなったよ」と出し、ひとりで続けられる。

仕様書以外に足したこと

  • 画像を読み込まなくても遊べるよう、最初から四字熟語の地図を5つ入れた（自由自在・四方八方・品行方正・一石二鳥・一日千秋）。字の中の閉じた部分に宝が入る。
  • 「みつけた！」の画面で、探し回った元の絵を大きく見せる（絵を見せる教材という狙いに合わせた）。
  • パソコンでの確認用にキーボード操作（矢印キー・スペース・C）。

作り方と、まだ確かめられていないこと

  • Claude Code で、3D・地図づくり・画面・通信を別々の担当に作らせて1ファイルに結合し、別の担当が採点表で採点して直す、を繰り返した。
  • 実際のiPadでの速さ、学校のネットワークでPeerJSの公開サーバーにつながるか、効果音の聞こえ方は未確認です。試していただけると助かります。
