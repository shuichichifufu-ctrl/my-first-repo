# ラウンド1 批評レポート（対象: versions/v1.html / 参照: バーチャファイター2）

実行時エラー: pageerror/console error ともに0件（全テスト中）。採点上限の5点キャップは適用しない。
計測方法: Playwright(chromium+swiftshader)で実際に起動。論理フレーム単位の計測はF[0]/F[1]のtにフックして取得。描画は約11fpsと遅いが、ロジックは60Hz換算で進むためフレーム値は有効。

### 1. 操作の反応 7点
- Jキー送信から次の描画時点で state=attack, t=5（実測4.2ms後）。入力から攻撃開始まで1フレーム以内。
- J+Lの同時押しで投げが出る。A/D移動とLガードの併用も可能。取りこぼしは見つからず。
- 減点: Lを押しながらJを押すと必ず投げになり、「ガードしながらパンチ」ができない。しゃがみ中は歩けない。横移動は0.042/フレームで遅い（1秒で約1.8進む程度）。

### 2. 三すくみ 6点
実測:
- 立ちガードに P/K はヒット0（ガード成立）。下段キックは立ちガードにヒット（8ダメージ）、しゃがみガードには0。中段Kはしゃがみガードで防がれ、しゃがみのみ（ガードなし）ではヒット(11)。上段Pはしゃがみでかわせる（ダメージ0）。上段/下段の区別は動く。
- 投げ: 立ち・ガード中・しゃがみ・しゃがみガード中のどれにも成立（各20ダメージ）。ガードが投げに負ける点は基準どおり。
- 投げの発生12F、パンチ6F。投げの入力と同時に相手がパンチすると、こちらがカウンターで8ダメージを受けて投げは潰れる。打撃は投げに勝つ。
- 投げ間合い: 距離1.2は成立、1.4は空振り。空振り時の全体硬直は48F。
- 減点: 投げ抜け(P+G)は掴まれて13F以内のみ有効。掴まれた側に見える合図は小さい文字「つかんだ！」だけで、見てから抜けるのは現実的でない。上段/下段の区別は「ガード＋方向」ではなく「しゃがみ＋ガード」方式で、立ちガードのままでも上段・中段は全部防げるため、ガードの敷居が低い。

### 3. 技の手応え 6点
- 発生(命中フレーム)を実測: パンチ6F、下段キック9F、キック11F、ひじ13F。全体F: パンチ約20、キック31、下段31、ひじ36。技ごとに違う。
- ヒット時: 6Fのヒットストップ（カウンターは8F）、白い球状のスパーク、画面シェイク、フラッシュ、カウンター表示、のけぞり姿勢。ガード時: 青いスパークと「ガード」表示、ヒットストップ3F。ヒットとガードは見て分かる。
- 減点: スクリーンショット(punch/kick)では当たりのエフェクトは半透明の丸い球1つだけ。技ごとの当たり方の違い（部位・方向）は見えない。ヒット後の有利不利はキックが-2F（ヒットしても攻撃側が先に動けない）、パンチは+1F程度で、技の使い分けの動機が薄い。音は未確認（ヘッドレスでは聞けないため評価対象外）。

### 4. CPU 4点
5種類のボットで検証（各約45秒、speed=8、複数試合）:
- 棒立ち(idle): CPU 3勝0敗。
- 前進しながらJ/Kを交互に連打(mashPK): **P1が4勝0敗**。CPUは連打で完封される。
- 投げ連打: P1が1勝、その後も試合は競る。
- ガード固めのみ: CPU 3勝0敗。
- 近づいてジャブ→ガードを交互にする「それらしい人間」: **CPU 5勝0敗**。
- つまり連打だけで勝てる（基準の「連打だけでは勝てない」に反する）一方、普通に守りを混ぜる相手には初心者が一度も勝てなかった。難度の向きが逆。CPUは相手の攻撃の発生(t===1)を見て確率で反応する作りで、距離は調整する（棒立ちではない）。
- 減点: 連打に弱く、まともなプレイに強い。投げには反応しない（投げは常に通る）。

### 5. キャラの動きと見た目 6点
- 3D人型。関節（肩・肘・股・膝・胴・首）があり、立ち・ガード・しゃがみ・パンチ・キック・ひじ・投げ・のけぞり・ダウン・勝ち・負けで姿勢が違う（スクリーンショットで確認）。KO後は仰向けに寝る。
- カメラは2人の中点を追い、距離で引く。
- 減点: 胴体は箱で、立ち姿が左右ほぼ同じ（色違いのみ）。姿勢は線形補間で、重みや体重移動は見えない。投げの「つかみ」姿勢は、投げ中のスクリーンショットではただ相手がのけぞって離れるだけに見え、掴んでいる絵にならなかった。リングアウトの瞬間、落ちた側がフレームの外に出て見えない（ringout.png）。

### 6. 勝敗の流れ 8点
実測で確認: 体力ゲージ(赤い遅れ表示つき)、ラウンド表示、60秒タイマー、リングアウト判定（縁で押されると場外→RING OUT!→相手に1本）、KO（K.O.!、仰向けにダウン）、2本先取でAKIRA WINS＋「Enterキーでもう一度」、Enterで再戦（ROUND 1に戻る）。
- 減点: タイムアップは今回ブラウザで実走確認していない（コード上は実装あり）。リングアウトは「押された時のみ」落ちる。自分で歩いて落ちることはできず見えない壁がある。

## 参照5点の勝ち負け
1. 3ボタンの読み合いの深さ: **負け**。ボタンは3つだが、全技が相手を自動で狙う（後述）ため、結局は「打つ・守る・投げる」の運ゲーになり、連打で勝てる。
2. 発生・硬直・間合いの明確さ: **負け**。数値は技ごとに違い測れるが、パンチ6F(100ms)は見てから反応できない。バックステップでも避けられない（P・K両方とも後退しながらでも被弾）。視覚的な予備動作の差が小さい。
3. 関節人型の重みある自然な動き: **負け**。関節はあるが補間が単純で体重が乗らない。
4. 横移動と3次元の駆け引き、リングアウト: **大負け**。横移動で攻撃をかわせた例が0回（下記）。リングアウトは機能するが、駆け引きと呼べる要素がない。
5. 当たり・ガード・投げの判別: **負け（差は小さい）**。当たり/ガードは色と文字で区別できる。投げは掴みが見えない。

**全体: 参照（バーチャファイター2）の勝ち。成果物は不合格。**

## 次ラウンドで直すべき最重要の1点
**横移動（サイドステップ）が何も避けられない。3Dにした意味がない。**
- 実測: 攻撃側は技を出す瞬間に、その時点の相手位置へ向きを固定する（startMoveでax/az=現在の向き）。当たり判定の横幅は±0.5。横移動の速度は0.042/フレームで、パンチ発生6Fの間に0.25しか動けない。
- 結果: 横移動を押し続けて(0/150/300ms)から相手が攻撃、攻撃と同時に横移動、攻撃を見てから横移動、のいずれでも、パンチ(6ダメージ)・キック(11)・ひじ(14)は全部命中した（計15回以上でかわせた回数0）。
- 直し方の方向: 横移動の速度を上げる（今の2倍以上）、直線技の横幅を狭める（±0.5→±0.3程度）、技の出始めに相手を追尾しない（向きは入力時点で固定し、発生中に動いた相手は外れる）、のどれか。その上で「横移動で外れた」ことが分かる表示（かわした時の音・文字）を足す。これができれば観点1・2・4・参照(4)が一度に動き出す。

## 小さな修正（最大5つ）
1. CPUを「連打に負けない・普通のプレイに負ける」へ逆転させる。連打ボットが4勝0敗、まともなボットが0勝5敗。
2. 投げの掴み姿勢が見えない。掴んだ時に両者が組み合う姿勢（grabbedが実質のけぞり）を描く。
3. 掴まれた側への投げ抜け合図を強くする（効果音・画面表示・猶予13Fの目安）。今は小さな文字のみ。
4. リングアウトでカメラが落ちる側を追う（今は画面外に消える）。
5. ヒット演出をスパーク球1つから、技ごとに形・向き・色が違うものに。キックは-2Fでヒットしても不利なので、技の使い分けが成立するよう硬直を調整。
