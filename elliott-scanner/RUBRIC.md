# 採点表（ラウンド1の前に固定。途中で書き換えない）

対象: エリオット波動でサードオブサード（第3波の中の第3波）の入口を探して通知するツール
参照: プロが手で数えた波動カウントと並べて見劣りしない検出（代理比較: 参照の優れた点5個）
水準: 通知された候補を、利用者が自分の目でチャートを見て「確かに第3波の入口に見える」と納得できる

## 参照（プロの手カウント）の優れている点5個（代理比較用）
1. 第2波が第1波の始点を割らないなど、鉄則ルールを1つも破らない
2. 第1波・第2波・第3波の入口という「位置」を、根拠となる価格水準（起点・戻り・突破点）で明示する
3. 大きな波動の第3波の中で、さらに小さな第1・2波が完了した「入れ子」構造を確認している
4. 自信がない局面は「数えない」と判断し、無理に候補にしない
5. 無効になる価格（これを割ったらカウント失敗）を必ず添える

## 観点（各10点満点）

1. 鉄則ルールの遵守
   7点… 上昇・下降どちらの向きでも、第2波が第1波の始点を割らない／第3波が1・3・5波のうち最短でない／第4波が第1波の領域に入らない、を機械的に判定し、破る候補を1件も出さない。ルールごとに単体テストがある。
   3点… ルール判定が一部だけ、または片方向のみ。破る候補が出ることがある。

2. サードオブサード局面の的確さ
   7点… 大きな次数で「第1波・第2波完了、第3波入口」を確認し、さらに第3波の中の小さな次数で「小1・小2完了、小3の入口」を確認した場合だけ候補にする（二重の入れ子）。フィボナッチの戻り率（第2波38〜78.6%、小2波も同様）を判定に使う。
   3点… 1つの次数の第3波入口を見ているだけ。入れ子の確認が無い。

3. 誤通知の少なさ（見送る判断力）
   7点… 判定に自信の度合い（スコア）があり、閾値未満は通知しない。無効化価格が明示され、無効化された候補は取り下げの扱いになる。同一銘柄の連日重複通知を抑える。合成データのノイズ相場・レンジ相場で候補が出ないことをテストで示す。
   3点… 閾値が無い。ノイズ相場でも候補が出る。重複通知する。

4. 再現性の検証
   7点… 既知の波形を埋め込んだ合成データで、検出できること（再現率）と、ノイズで出ないこと（誤検出率）を数値で出す検証スクリプトがあり、結果を報告できる。過去データでの検証手順も用意されている。
   3点… 手動で数本のチャートを眺めただけ。数値が無い。

5. 通知の読みやすさ
   7点… 通知1件に、銘柄名、向き（上昇/下降）、現在の局面、起点・戻り・突破点・無効化価格、確度スコア、根拠チャート画像（波動番号と水準線つき）が含まれ、スマホで意味が分かる日本語。
   3点… 銘柄名と一言だけ。画像や無効化価格が無い。

6. 対象範囲と取りこぼしの無さ
   7点… 株（日米）・FX・コモディティを設定ファイルで一括管理し、銘柄の追加・削除がコード変更なしにできる。取得失敗の銘柄があっても全体は止まらず、失敗した銘柄を通知の末尾で報告する。データ欠損・上場間もない銘柄・出来高ゼロの日を扱える。
   3点… 銘柄がコード内に固定。1銘柄の取得失敗で全体が止まる。

7. 自動実行の安定性
   7点… GitHub Actionsが平日に毎日1回実行し、失敗時は原因が分かるログが残る。秘密情報（Webhook URL）はSecretsで管理しコードに書かない。ローカルでも同じコマンドで動く。ドライラン（通知せず結果表示）モードがある。
   3点… 手動実行のみ、または秘密情報が平文。

## 実機確認待ちにする項目（このクラウド環境で検証できない）
- 実際の価格データ取得（Yahoo Finance等へのアクセスが遮断されているため）
- Discordへの実送信
- GitHub Actions上での実行
これらはコードから確認できる事実（例外処理の有無、Secretsの参照方法など）だけで採点し、実測が要る部分は「実機確認待ち」と明記する。
