# エリオット波動スキャナ（サードオブサード検出）

株・FX・コモディティの日足を毎日チェックし、**サードオブサード（第3波の中の第3波）の入口**に見える銘柄をDiscordに通知します。

> 機械的な判定です。エリオット波動の数え方は人によって変わるため、これは「見るべき候補を絞る道具」であり、当たる予測ではありません。売買の助言ではありません。

## 何を「入口」と判断するか

上昇の場合（下降は上下を反転して同じ処理）。

1. **大きな波**（値幅がATRの7倍以上で転換）で 0 → 1 → 2 が完了。2は1の38.2〜78.6%戻し、かつ0を割らない。
2. **小さな波**（ATRの2.5倍以上で転換）を2の安値から数え、(i) → (ii) が完了。(ii)は(i)の38.2〜78.6%戻し、かつ2を割らない。
3. 現在値が (i) の高値を超えて（＝入口）、超え幅が(i)の61.8%以内。または超える直前（準備）。
4. (iii)が1.618倍まで伸びれば大1波の頂点を超えること、2.618倍まで伸びれば大3波が大1波の長さに届くこと（届かない波は第3波として不自然）。
5. 確度スコア（フィボナッチの当てはまり、トレンド、局面）が65以上。直近250本に「大1波の3倍超の下落」があり、その半値戻しにも届いていない場合は、下落途中の反発（調整波の可能性）とみなして40点減点する（下降は上下反転）。

**入口では判定できない鉄則**: 第4波が第1波に入らない／第3波が最短でない（第5波との比較）は、第4・5波がまだ無いので実測できません。代わりに、標準的な比率で最後まで進んだ場合の推進波を仮に置き（(iii)=2.618倍、第4波=第3波の38.2%戻し、第5波=第1波と同じ長さ）、完成した推進波の鉄則判定 `check_impulse_rules` に通しています。仮定にもとづく判定です。

**判定していないこと**: 大1波が5つの小さな波でできているか（推進波らしいか）は判定していません。通知に「大1波の内側の脚の数」を表示するだけです。

## 使い方

```bash
cd elliott-scanner
pip install -r requirements.txt
python -m pytest -q                       # テスト
python -m scanner.verify                  # 合成データでの検証（基準を満たさなければ終了コード1）
python -m scanner.run --dry-run           # 通知せず結果を表示（要ネットワーク）
python -m scanner.replay --symbol USDJPY=X --period 10y   # 過去チャートで検証（要ネットワーク）
```

銘柄は `tickers.yaml` を編集するだけで追加・削除できます。

## 毎日の自動実行（GitHub Actions）

1. Discordでチャンネルの「連携サービス → ウェブフック」を作成し、URLをコピー
2. GitHubのリポジトリ → Settings → Secrets and variables → Actions → New repository secret
   名前 `DISCORD_WEBHOOK_URL`、値にURLを貼る
3. Actionsタブ → `elliott-scan` → Run workflow（最初は dry_run のまま）で動作確認

平日 日本時間 翌朝6:30（米国市場の引け後）に自動実行します。

## 検証の現状（正直な但し書き）

- 合成データ（既知の波形を埋め込む）での検出率と誤検出率は `scanner.verify` で確認できます。ただし合成データは検出器の想定に近く、**実チャートでの当たりやすさを保証しません**。
- 波の大きさは相場ごとのブレ（ATR）を基準にしています。大1波が約7ATRより小さい相場は、大きな波として数えないため検出されません（`python -m scanner.verify --sweep` で条件別の検出率を確認できます）。戻り率が38.2%ちょうどに近いものは検出率が下がります（雑音で測定値が浅く出るため）。
- 確度スコアは手作りの加点で、実績との相関は未検証です。
- 実データの取得（Yahoo Finance）、Discord送信、Actions上の実行は、開発環境のネットワーク制限のため**未確認**です。最初のActions実行結果を確認してください。

## 運用上の注意

- GitHub Actionsの定期実行は、リポジトリに60日間動きが無いと自動で止まります。止まったらActionsタブから再度有効にするか、Run workflowで手動実行してください。
- `main` ブランチに取り込まれるまで、定期実行は動きません（スケジュールは既定ブランチのものだけが実行されます）。
