## 2. 新しく分かったこと（引継書の確認項目に対応）

1. 残り半分の決済方法（ほぼ解消）。残り半分は、次の安値または高値（目標2）で決済する。次の目標が遠い、または無いときは、チャネルを引いて利確位置の参考にする（⑦⑨）。目標2に届かず優位性が消えたときは、ラインを超えた時点で全決済する（③⑧）。損切りを建値へ引き上げる記述は、どの実例にも出てこない（未解消）。
2. 第1利確の「直近高値」（解消）。1時間足で見て、エントリー価格より先にある最寄りの直近高値（安値）。無い場合は、前回のレジスタンスゾーンを節目として使う（⑧）。
3. 4時間足の長期線（未解消）。本文は「20SMA」としか書かず、長期線の本数は実例から決まらない。80と120の両方を検証する。
4. 押しの深さ（一部解消）。40〜80EMAが適正帯（②⑥）。ただし勢いが強いときは浅い戻しもあり得る（⑧）。浅い側の下限は、数値では書かれていない。
5. 切り下げラインの引き方（未解消）。どの高値を結ぶか、何本かは書かれていない。
6. ブレイクの判定（未解消）。終値かヒゲかの記述は無い。
7. 1時間足のクロスからの経過時間（未解消）。「デッドクロス後の収束→拡散」「クロス後の下降3波目」といった局面の表現だけで、時間は書かれていない。
8. 環境認識の実際（新事実あり）。第3章を参照。
9. 負けた例（確認）。実例に負けは無い。実例集は書き手が選んだ一部で、「ほとんど似ている形ばかりなので割愛」と書いている。
10. 時間帯（未解消）。ゴールドの例⑦を含め、時間帯のルールは書かれていない。

## 3. 既存の理解の修正点

- 上位足の条件は緩い。日足が下降のままロング（①③）、日足が「やや上昇気味のレンジ」でショート（⑥）、日足・4時間足が「はっきりしない」状況でショート（⑩）の例がある。本書の運用は「上位足が明確に逆行していなければよい」に近い。
- 上位足が微妙なときは利確を早める（⑥⑩）。基準は「伸び代が少なそうなら素早く」という裁量で、数値では書かれていない。
- 1時間足は「GC／DC後の収束→拡散」「GC／DC後の下降3波目」といった形を重視している（②⑧⑨）。
- 通貨ペアはFXだけでなくゴールドも含む（⑦）。
- p143の補足：この手法は「テクニカルのみのルール」で、経済指標があっても条件が揃っていればエントリー可能。書き手が2025年10月1日のポンドドルでロング利確した例を挙げている（チャートは未受領）。したがって、指標カレンダーによる見送りフィルターは原典に無い。
- v1の「金曜夜は見送り」は、実例④の解説に基づいていたため、根拠から外した（④の解説は未受領）。

## 4. 手法の確定版（検証用）

「確定」は本文または実例で確認できたもの。「基準案」は機械化のために置いた案で、検証が必要。「未確認」は決められなかったもの。

**準備（上昇の場合。下降は逆）**

- 日足：ZigZag（5,1,1）、20SMA、100SMA（確定、前のチャットの内容）
- 4時間足：ZigZag、20SMA、長期線（80か120、未確認）
- 1時間足：20SMA、80SMA（確定）
- 15分足：EMA 10・20・40・80・320（確定）

**エントリー条件**

1. 1時間足で20SMAが80SMAをクロスした後の形（収束→拡散、または3波目）を監視対象にする。クロスからの許容時間は未確認で、検証で変動させる。
2. 環境フィルターは基準案として「日足・4時間足が、明確に逆行する形ではないこと」。強度を3段階（厳格／標準／なし）で比較し、本命は標準。
3. 15分足のパーフェクトオーダーが完成している（確定）。
4. 直近高値（安値）をいったんブレイクする（確定）。終値かヒゲかは未確認で、両方検証する。
5. 押しで切り下げ（切り上げ）ラインができる（確定）。押しの適正帯は40〜80EMA（基準案）。80EMA超えの深い押しは除外。浅い押し（20EMA帯）は、除外するかを検証で変動させる。
6. 切り下げラインのブレイクの足でエントリーする（確定）。ラインの引き方は未確認。基準案は戻り高値を2〜3個結ぶとし、個数を変動させる。

**決済**

- 損切り：エントリー時の押しの底（天井）の外側（確定）。余白は未確認。
- 第1利確：1時間足で、エントリーの先にある最寄りの直近安値（高値）で半分。無ければ前回のレジスタンス（サポート）ゾーン（確定）。
- 残り半分：次の安値（高値）で決済。目標が遠いとき、または無いときは、チャネルの反対側を目安に決済（確定だが、チャネルの引き方は裁量で機械化が難しい）。目標到達前に、直近の戻り高値（安値）を更新して優位性が消えたら全決済（確定、③⑦⑧⑨）。
- 損切りの引き上げ：実例に記述が無い（未確認）。検証では、引き上げなし／建値へ引き上げ／戻り高値（押し安値）の更新に合わせて引き上げ、の3パターンを比較する。

**検証で気をつけること**

- チャネルでの決済は、機械化できる形（例：1時間足のZigZag高値・安値を結ぶ線）に直すと、書き手の運用とずれる可能性がある。
- 実例の期間（2024年10月〜2025年10月）は、検証の調整用データから外すか別枠にする。実例は選ばれた成功例で、勝率の根拠にならない。
- 日足・4時間足の「判断」は裁量の要素が大きい。環境フィルターの強度を変えたときに成績がどう変わるかを見ること。
