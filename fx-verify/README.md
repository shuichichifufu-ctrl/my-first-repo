# fx-verify: 15分足FXデイトレ手法の検証

書籍『15分足FXデイトレ最強手法 決定版』の手法を、本書が数値で決めていない部分(裁量部分)を数値に置き換えてバックテストし、
「勝てる / 勝てない / 保留」を判定するための道具です。仕様の正本は引継書(第3〜5章・第8章)と `INTERFACES.md` です。

## いまの状態(必ず読んでください)

- ea-lab リポジトリと実際のFXデータは、この環境にはありません。
- そのため、ゲートの基準値(PFなどの合格ライン)・スプレッド・スリッページは **未設定(placeholder)** です。基準値は作っていません。
- 未設定のうちは、判定は必ず **「保留」** になり、レポートの最初に不足しているものが書かれます。
- `--synthetic`(合成データ)の結果は、乱数で作ったデータの動作確認用です。**勝てる・勝てないの根拠にはなりません。**

## すぐ動かす(合成データで動作確認)

```bash
cd fx-verify
pip install -r requirements.txt
python run_all.py --synthetic --years 3 --seed 0 --out out/
```

`out/report.md`(判定レポート)と `out/result.json`(再現用データ)ができます。結論は「保留」になるのが正しい動作です。

テストは次のコマンドです。

```bash
cd fx-verify
python -m pytest
```

## 実データの形式

### ファイル名

`--data-dir` で指定したフォルダに、通貨ペアごとに1ファイルずつ置きます。既定のファイル名は次のとおりです。

| 通貨ペア | 15分足(既定) | 1分足(任意) |
|---|---|---|
| USDJPY(ドル円。主ペア) | `USDJPY_M15.csv` | `USDJPY_M1.csv` |
| EURUSD | `EURUSD_M15.csv` | `EURUSD_M1.csv` |
| GBPUSD | `GBPUSD_M15.csv` | `GBPUSD_M1.csv` |
| EURJPY | `EURJPY_M15.csv` | `EURJPY_M1.csv` |
| AUDUSD(必要なら) | `AUDUSD_M15.csv` | `AUDUSD_M1.csv` |

- 通貨ペア名は大文字6文字です(`--pairs USDJPY EURUSD GBPUSD EURJPY`)。
- ファイル名の形は `--file-pattern "{pair}_M15.csv"` で変えられます(`{pair}` が通貨ペア名に置き換わります)。
- 15分足のファイルが無く、1分足だけある場合は `--m1-pattern "{pair}_M1.csv"` を付けると、1分足から15分足を作ります。
- ファイルが見つからないペアは「評価できなかったペア」としてレポートに書かれます(主ペアのドル円が無いと、判定は保留です)。
- 実データの置き場所は `fx-verify/data/` が目安です(`*.csv` は git に入りません)。

### 列名

1行目にヘッダを付ける形が基本です。**時刻・始値・高値・安値・終値**は必須、出来高は任意です。

```csv
time,open,high,low,close,volume
2020-01-02 00:00:00,108.610,108.650,108.590,108.640,812
2020-01-02 00:15:00,108.640,108.690,108.630,108.670,640
```

| 列 | 意味 | 受け付ける名前 |
|---|---|---|
| 時刻 | **足の始値時刻**(その足が始まった時刻) | `time` / `datetime` / `timestamp`(または `date` と `time` の2列) |
| 始値・高値・安値・終値 | 価格 | `open` `high` `low` `close`(`o` `h` `l` `c` も可) |
| 出来高 | 無くてもよい | `volume` / `vol` / `tick_volume` |

- MT4形式のヘッダなしCSV(`2020.01.02,00:15,108.640,108.690,108.630,108.670,640`)も読めます。
- `#` で始まる行はコメントとして無視されます。
- 価格は **スプレッドを含まない値(BID)** を想定しています。コストは別に計上します(下の「スプレッドとスリッページ」)。
- 日足100本分の移動平均などの助走が要るため、データは学習用と検証用に分けても足りる長さが必要です。
  どれだけ必要かは、実データの期間を見て決めてください(目安の数字はここでは決めていません)。
- 週末の足は無くてかまいません。

### 時刻の基準(大事)

日足・4時間足の区切りは「サーバー時間」で決まり、結果が変わります。CSVの時刻が何の基準かを `--source-tz` で教えてください。

| `--source-tz` | CSVの時刻 | 使いどころ |
|---|---|---|
| `utc`(既定) | UTC(世界標準時) | UTCで書き出したデータ |
| `fixed` | UTC+固定時間(`--source-offset 2` で GMT+2 固定) | 夏冬の切り替えが無いデータ |
| `ny_close_server` | MT4でよくある時間(冬 GMT+2、米国夏時間のあいだ GMT+3。ニューヨーク17時で日足が切り替わる) | MT4/MT5のサーバー時間のまま書き出したデータ |

検証では、この区切りを GMT±1時間ずらして成績を確かめます(GMTずらし)。

## ea-lab につないだあとにやること

1. **ゲート基準値を転記する**(いちばん大事。ここを埋めない限り「勝てる / 勝てない」は出ません)
   - ea-lab の `DESIGN.md` にある「Phase-0 優位性証明ゲート」と「昇格ゲート」の基準を探します。
   - 転記先は次のどちらかです(やりやすいほうで)。
     - **JSONで渡す**: `templates/phase0.template.json` と `templates/promotion.template.json` をコピーして、
       ea-lab の項目に合わせて `rules` を書き換えます。`threshold` が `null` のままのルールは「未転記」で、判定は保留になります。
       実行時に `--gates-json phase0.json promotion.json`(1つ目が Phase-0、2つ目が昇格)で渡します。
     - **コードに書く**: `core/gates.py` の `PHASE0_GATE` と `PROMOTION_GATE` に `GateRule(...)` を足します。
   - 1ルールの書き方は次のとおりです。

     ```json
     {"name": "ea-labでの項目名", "metric": "pf", "op": ">=", "threshold": <ea-labの値>, "scope": "train", "source": "DESIGN.md の何節から転記したか"}
     ```

   - `metric` に使えるのは次の名前です(`core/metrics.py`)。
     `n_trades` `n_long` `n_short` `win_rate` `pf` `avg_r` `expectancy_r` `total_r` `avg_win_r` `avg_loss_r`
     `max_dd_r` `max_consec_losses` `partial_rate` `avg_cost_r` `gross_avg_r`。
     ea-lab のゲートに、ここに無い指標があるときは `core/metrics.py` への追加が必要です。
   - `op` は `>=` `>` `<=` `<` `==`。`scope` は、そのルールを使う区間です。

     | scope | 使う区間 |
     |---|---|
     | `train` | ドル円の学習用期間(段階Cの合否判定にも使う) |
     | `oos` | ドル円の検証用期間(アウトオブサンプル) |
     | `pair` | 他の通貨ペアの全期間(再調整なし) |
     | `gmt_shift` | GMTずらし(±1時間) |
     | `all` | すべての区間 |

   - 学習用期間でゲートに届く設定が1つも無ければ、段階Dを省略して「勝てない」と判定します(引継書 第4章)。
     ゲートが未転記の間は打ち切らず、全段階を回して「保留」にします。

2. **スプレッドとスリッページを転記する**
   - ea-lab の既存設定(`DESIGN.md` / `RUNBOOK.md` など)の値を、pips単位で `templates/costs.template.json` をコピーした `costs.json` に書きます。
   - 通貨ペアごとのスプレッド(`spread_pips`)と、1回の約定あたりのスリッページ(`slippage_pips`)です。出典(`source`)も必ず書きます。
   - `null` のままだと「未設定」で、段階A〜Eは実行せずに「保留(コスト未設定)」のレポートだけを出します。
   - 実行時に `--costs-json costs.json` で渡します。
   - 合成テスト用のコスト(`core/config.py` の `synthetic_test_config`)は「テスト用・実値ではない」ものです。実データでは使わないでください。

3. **学習用期間と検証用期間の分け方を決める**
   - 実データの期間を確認して、学習用期間の終わりを決め、`--train-end 2022-12-31` のように渡します(省略すると全期間の60%の位置を月初に丸めます)。
   - **検証用期間や他の通貨ペアの成績を見てから、設定や分け方を選び直さないでください。**
     選び直すと判定は「保留」寄りになります(引継書 第8章)。

4. **実行する**

   ```bash
   cd fx-verify
   python run_all.py --data-dir data --pairs USDJPY EURUSD GBPUSD EURJPY \
       --file-pattern "{pair}_M15.csv" --source-tz ny_close_server \
       --costs-json costs.json --gates-json phase0.json promotion.json \
       --train-end 2022-12-31 --out out/
   ```

5. **レポートを読む**: `out/report.md` の最初に「勝てる / 勝てない / 保留」と一番の理由が書かれています。
   保留のときは、不足しているものが箇条書きで出ます。それを埋めて、もう一度実行します。

## 判定の規則(引継書 第0章)

| 結論 | 条件 |
|---|---|
| 勝てる | ea-lab の既存ゲートを、検証期間外のデータ(アウトオブサンプル)と複数通貨ペアで通過した |
| 勝てない | どの妥当な定義でもゲートを通過しない、または通過が一部の設定に限られ曲線当てはめと判断される |
| 保留 | データ不足などで判定できない(不足しているものを明記) |

次のどれかに当てはまるときは、常に「保留」です。

- 合成データである
- ゲート基準値が未転記(または閾値が空のルールが残っている)
- スプレッド/スリッページが未設定
- 実データが無い、検証用期間が無い、必要な通貨ペア(EURUSD・GBPUSD・EURJPY)が欠けている
- 検証用期間や他ペアの結果を見てから設定を選び直した(凍結記録で検出。下の「選び直しの検出」)
- 検証用期間を見たのに、実行をまたいで残る凍結記録が無く、『選び直しなし』を確認できない
- 段階の実行中にエラーが出た
- 選んだ設定に、原典に無い追加フィルター(D10)が入っている(原典準拠の判定とは別に行う必要があるため)

## 選び直しの検出(引継書 第8章)

- `run_all.py` は、段階Cで設定を選んだ**直後**に、その設定を凍結記録 `<out>/freeze.json` に書きます(`--freeze-file` で場所を変えられます)。
  同じ記録が段階D・Eにも渡り、「検証用期間・他ペアを見た」ことも記録されます。
- **同じ記録ファイルを使う再実行**で、検証用期間を見たあとに設定(または学習用期間の終わり)が変わっていると、
  「選び直し」として検出され、`meta.reselected=True`・判定は保留になります。一度立った印は消えません。
- 記録ファイルが壊れている・書き換えられている場合も「選び直し」扱いです。壊れて読めない場合は、黙って作り直さず終了します
  (新しい検証を始めるときだけ、理由を記録したうえで `freeze.json` を消してください)。
- 第4章の「選び直しの有無: なし」は、この記録で確認できたときだけ出ます。記録が無ければ「未確認」と書きます。

## 段階Cの「台地の中央」選び

- 近傍は**自分自身を除く**隣の水準(順序のある軸のみ)。順序のない軸(モード切替など)の水準どうしは隣と見なしません。
- まず『台地の点』(近傍の有効な点すべてとPF差が目安以内で、平均Rの符号が同じ点)だけを候補にし、その中で近傍平均が最大の点を選びます。
  尖った山・谷は台地ではないので選ばれません。
- 台地の点が無い、または順序のある軸が1つも無いときは**選びません**(`selection_info.no_plateau=True`)。
  最高点をそのまま選ぶことはせず、段階D・Eは実行しないで理由をレポートに書きます。

## レポートの構成(引継書 第6章)

1. 結論と一番の理由 / 2. ゲートの項目ごとの合否 / 3. 原典準拠の基準設定(段階A)の成績 / 4. 選んだ設定・選び方・試した設定の総数 /
5. 主要な成績(取引回数・勝率・PF・平均R・期待値R・最大ドローダウン・年別・通貨ペア別・買い売り別) / 6. 感度分析 /
7. ベンチマーク(ランダムエントリー)との比較 / 8. 条件ごとの通過数 / 9. 原典に無い補完と影響 / 10. 限界と未確認事項

## ファイル構成

| ファイル | 役割 |
|---|---|
| `run_all.py` | 段階A→Eを通しで実行して `report.md` と `result.json` を出す入口 |
| `report.py` | 判定(`decide_verdict`)とレポート生成(`build_report`)、成績集計・感度分析表・通過数の表 |
| `core/` | データ読込・指標・ゲートの枠・成績指標など(基盤) |
| `strategy.py` | バックテスト本体(`run_backtest` / `run_benchmark_random`) |
| `stages` | 段階A〜E(`INTERFACES.md` §6。`run_all.py` はここの関数だけに依存する) |
| `templates/` | ゲート基準・コスト設定を転記するためのひな形(値は空) |
| `tests/` | テスト(`python -m pytest`) |

`fx-verify/` の外のファイル(ea-lab を含む)は変更しません。
